Architecture memo: C1-SR spatial source reuse

SHIP authorizes parent review and preregistration only—not implementation acceptance or a performance claim.

Hypothesis assessment: credible but unproven. The accepted C1 kernel reads Y and UV inside the 48-channel dimension (`NV12MobileNetV2Stem.metal:16-31`). Across valid outputs this issues approximately 5,386,800 Y reads and 5,386,800 UV reads. The repaired profile measures C1 GPU stem p50 at 0.239458 ms versus B2 at 0.289583 ms, so removable GPU cost exists. No counter attributes that cost specifically to texture traffic; Apple’s texture cache may already absorb much of the redundancy.

Proposed fixed schedule:

- Candidate name: `C1-SR`; it remains an experimental C1 implementation, not C4.
- Input remains the accepted resized 224×224 video-range NV12 textures: `r8Uint` Y and `rg8Uint` UV.
- Output remains Float32 CHW `[48,112,112]` in the same persistent activation buffer.
- One command buffer, one compute encoder, unchanged Core ML tail and synchronization.
- Fixed output tile: 4×4 spatial positions.
- Dispatch: 28×28 threadgroups, 128 threads per group. No tile-size search is authorized.
- Each group cooperatively loads the tile’s unique 9×9 Y patch and 5×5 UV patch. Use raw integer threadgroup storage, preferably padded `uint y[9][10]` and `uint2 uv[5][6]`—about 600 bytes.
- Interior texture work becomes 81 Y plus 25 UV reads per tile. Including right/bottom edges, the full dispatch performs approximately 82,322 source-texture reads, versus 10,773,600 in current C1: a structural reduction of about 131× before cache effects.
- Execute exactly one `threadgroup_barrier(mem_flags::mem_threadgroup)` after loading. All 128 threads must reach it; there are no pre-barrier returns.

Thread and SIMDgroup ownership:

| Element | Ownership |
|---|---|
| Threadgroup | One 4×4 output tile, all 48 channels |
| Four 32-lane SIMDgroups | Two spatial halves × two four-channel-residue blocks |
| Eight-lane cohort | One channel residue across eight spatial positions |
| Lane | Six channels: `residue + 8q`, `q=0…5`, for one spatial position |
| Registers | Six channel accumulators plus current Y/Cb/Cr values and weight temporaries |
| Threadgroup memory | Raw Y/UV source patch, read-only after the barrier |

For linear thread `tid`:

```text
simdgroup       = tid / 32
simdLane        = tid % 32
spatialHalf     = simdgroup / 2
channelBlock    = simdgroup % 2
localSpatial    = spatialHalf * 8 + simdLane % 8
channelResidue  = channelBlock * 4 + simdLane / 8
channel(q)      = channelResidue + 8*q
```

Within each SIMDgroup, lanes 0–7 load the current tap’s normalized Y/Cb/Cr from threadgroup memory for their eight spatial positions. `simd_shuffle` broadcasts from source lane `simdLane % 8` to the other three channel cohorts. Each lane updates its six accumulators. This gives coherent channel-major writes in eight-lane cohorts while each source value serves 24 channels per SIMDgroup.

Exactness requirements:

- Preserve raw integer texture reads; no sampler, filtering, normalized texture format, RGB clamp, or precision change.
- Preserve BT.601 video-range decoding exactly: `(Y−16)/219`, `(Cb−128)/224`, `(Cr−128)/224`.
- Preserve nearest-sited UV geometry: source tap `(x,y)` uses UV `(x/2,y/2)`.
- Preserve tap order `ky=0…2`, `kx=0…2` and per-channel accumulation order.
- Use the unchanged `sourceWeights`, per-tap `sourceOffsets`, and folded `bias`.
- Do not aggregate chroma weights or adopt the R5 polyphase operator.
- Apply ReLU6 only after all valid taps.
- Preserve SAME-bottom/right behavior: `x=2*ox+kx`, `y=2*oy+ky`; invalid coordinate 224 skips the entire tap, including its source offset.
- Since 112 is divisible by four, every output tile is complete. Right/bottom loader reads are guarded and filled with inert values; compute-side validity controls whether the tap contributes.

Primary risks:

- Current texture caching may already coalesce channel-repeated reads, leaving barrier, shuffle, and threadgroup-memory overhead as a net loss.
- Six accumulators and unrolled weight accesses may raise register pressure or reduce occupancy.
- The 128-thread spatial-major schedule exposes less independent thread-level work than current C1.
- Weight traffic and arithmetic remain unchanged and may dominate after source reuse.
- Compiler reassociation/FMA decisions may change floating-point results despite algebraic identity.
- The Core ML tail dominates end-to-end time. Using current evidence, T1 requires approximately 0.125767 ms improvement over C1—8.05% of C1 end-to-end and about 52.5% of the profiled C1 GPU-stem p50.

Single preregistered comparison:

- Run one three-way `B2 / C1 / C1-SR` experiment; never compare a fresh candidate only with historical numbers.
- Same 64-input corpus, Float32 tail, `.all` compute policy, bridge, input order, timing boundary, Release configuration, and environmental metadata.
- Five separate processes; 20 warmup triples and 240 measured triples per process.
- Cycle all six execution permutations exactly 40 times per batch, giving every path 80 observations in each ordinal position.
- Preserve raw records and calculate paired B2−C1-SR and C1−C1-SR differences with a preregistered deterministic block bootstrap.
- Correctness precedes timing: unchanged `≤1e-5` activation threshold, `≥0.995` task agreement, full R7 top-1/top-5/probability reporting, zero C RGB bytes, and zero PlaneFuse element-copy bytes.
- Retain C1-SR only if it lowers end-to-end p50 versus C1 by at least 5% with a positive paired 95% CI.
- Competition success remains only unchanged T1: at least 10% lower end-to-end p50 than fresh strongest B2 with a positive paired CI.
- If C1-SR fails the C1 retention gate, reject it, retain C1, freeze performance research, and productize the honest result. No follow-up tile tuning or R6.5 revival.
